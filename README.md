Epic Cadence Scheduling & Analytics Project

Live Link: https://ianifill1996.github.io/EpicCadenceSimulator/

Project Overview
This project is a healthcare scheduling and analytics portfolio project inspired by workflows commonly associated with Epic Cadence.
The goal of the project is to demonstrate how scheduling operations, system design, data analytics, and business intelligence can work together to support patient access and operational decision-making within a healthcare organization.
The project combines:
•	A front-end scheduling simulator
•	Healthcare scheduling business requirements
•	Scheduling workflow and system design concepts
•	Excel-based scheduling data
•	Power BI analytics and visualization
•	Operational healthcare metrics
Disclaimer: This is an independent educational portfolio project. It is not affiliated with, endorsed by, or developed using proprietary materials from Epic Systems Corporation. The project uses simulated data and independently designed workflows.
 
Business Problem
Healthcare organizations manage large numbers of appointments across departments, providers, locations, and patient populations.
Scheduling teams need systems that allow them to efficiently identify appointment availability while operational leaders need analytics that help them understand scheduling performance.
This project explores both sides of that workflow:
Operational Workflow
•	Selecting departments and providers
•	Reviewing appointment availability
•	Scheduling patients
•	Preventing scheduling conflicts
•	Tracking scheduling activity
Analytics Workflow
•	Monitoring appointment volume
•	Evaluating appointment status
•	Comparing departments and providers
•	Identifying scheduling trends
•	Measuring operational performance
 
Project Components
1. Cadence Scheduling Simulator
The scheduling simulator was developed using:
•	HTML
•	CSS
•	JavaScript
The simulator demonstrates a simplified healthcare scheduling workflow where users can interact with departments, providers, appointment availability, and scheduling information.
The application is intended to demonstrate system analysis, workflow design, and front-end development concepts rather than reproduce the Epic Cadence application.
 
2. Business Requirements
The project includes a Business Requirements Document describing the proposed scheduling workflow and system requirements.
Key concepts include:
•	Department-based scheduling
•	Provider availability
•	Prevention of overlapping appointments
•	User access and scheduling permissions
•	Scheduling activity tracking
•	Appointment modification and cancellation tracking
•	Operational reporting
•	Data export capabilities
•	Web and mobile accessibility considerations
 
Power BI Scheduling Analytics Dashboard
The Power BI portion of the project transforms simulated scheduling data into operational insights.
The dashboard demonstrates how healthcare organizations could monitor scheduling activity and identify opportunities to improve patient access and operational efficiency.
Analytics Areas
The dashboard evaluates areas such as:
•	Total appointment volume
•	Appointment status
•	Completed appointments
•	Cancelled appointments
•	No-show activity
•	Department scheduling performance
•	Provider scheduling activity
•	Scheduling trends
•	Appointment utilization
These metrics can help operational teams identify patterns that may affect patient access, provider utilization, and scheduling efficiency.
 
Data Analysis Workflow
The analytics portion follows a structured workflow:
Business Question → Data Preparation → Data Analysis → Visualization → Operational Insight
The process includes:
1.	Identifying scheduling-related business questions
2.	Organizing simulated appointment data
3.	Preparing the dataset for analysis
4.	Creating calculations and performance metrics
5.	Building Power BI visualizations
6.	Interpreting results from an operational healthcare perspective

Project Objective
The purpose of this project is to demonstrate the connection between healthcare operations, application analysis, system design, and data analytics.
Rather than focusing only on building a dashboard or application, the project approaches scheduling as an end-to-end business workflow:
Healthcare Scheduling Workflow → System Requirements → Application Design → Operational Data → Analytics → Business Insight
This approach reflects the type of cross-functional thinking required in healthcare IT, application analyst, business analyst, and healthcare data analyst roles.
